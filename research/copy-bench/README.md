# copy-bench · 다른 앱 문구 캡처 넣는 곳 (문구 리서치 3단계)

헤드가 폰에서 찍은 캡처를 앱별 폴더에 넣으면, Claude가 읽어서 유형별 실제 문구 표(`<앱>/copy.md`)로 옮긴다. 지금은 폴더만 있고 캡처는 0장이다.

## 앱마다 찍을 화면 (있는 것만, 앱당 10~20장이면 충분)

우리 인벤토리(`research/copy-inventory.md`)의 유형 11개에 맞춘 목록이다.

1. **버튼**: 주 버튼이 보이는 화면 2~3장(신청 · 참여 · 시작하기 같은 것)
2. **상태**: 목록 카드의 상태 배지(모집 중 · 마감 · 참여 확정 등)
3. **확인 시트**: 신청 · 참여 전에 뜨는 확인 창
4. **완료**: 신청 완료 · 기록 완료 화면이나 토스트
5. **취소**: 참여 취소 · 일정 취소 확인 창과 취소 뒤 화면
6. **빈 상태**: 목록이 비었을 때(모임 없음 · 기록 없음 · 알림 없음)
7. **에러**: 입력 틀렸을 때 · 정원 마감 · 네트워크 오류
8. **알림**: 알림 목록 화면, 받은 푸시 알림(잠금 화면 캡처)
9. **안내문**: 규칙 · 안전 수칙 · 공개 범위 · 위치 권한 안내
10. **브랜드 슬로건**: 첫 실행 화면 · 온보딩 첫 장
11. **소개문**: 온보딩 설명 · 앱 안 "서비스 소개"

## 파일 이름

`<번호>-<유형>-<짧은 설명>.png` 예: `03-확인시트-참여신청.png`, `06-빈상태-모임없음.png`. 번호는 앱 안에서 찍은 순서. 이름이 어려우면 `IMG_1234.png` 그대로 넣어도 되고, 유형은 Claude가 판단한다.

## 찍기 전에

- 다른 사람의 이름 · 프로필 사진 · 연락처 · 채팅 내용이 보이면 가리고 찍는다(개인 정보는 표에 옮기지 않는다).
- 로그인이 필요한 화면은 헤드 계정으로만. 비밀번호 · 결제 정보 화면은 찍지 않는다.
- 상태 바 시각은 그대로 둬도 된다(문구가 아님).

## 옮길 때의 원칙 (Claude)

- 짧은 화면 라벨(버튼 · 배지 · 탭 이름)은 그대로 옮기고, 두 줄 넘는 문장은 그대로 베끼지 않고 패턴으로 적는다: 구조 · 길이(자 수) · 어미 · 핵심 낱말 · 정보 순서.
- 캡처에서 읽은 것만 적는다. 안 보이는 부분을 짐작해 채우지 않는다.
- 결과는 `<앱>/copy.md`에 유형별 표로, 비교는 `research/copy-benchmark.md`에 반영한다.
