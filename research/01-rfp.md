## 1. 배경·문제 (왜 지금)

- 혼자 사는 20~30대 직장인이 퇴근 후 운동을 하고 싶지만, 혼자 시작하기는 막막하고 동호회는 가입·정기 참석·친목이 부담스러워 결국 아무것도 시작하지 못한다. (MANUAL §1)
- 러닝 크루는 늘었지만 달리기 하나에 묶여 있다. 달리기가 아니어도 조깅·따릉이·산책·하이킹을 다 같이 하면 재밌겠다는 데서 출발했다. (헤드, BRAND 시작 계기)
- 과금 없음: 회차 신청은 무료. 라이트 바이크 회차의 따릉이 요금만 따릉이에서 각자 낸다. (헤드, MANUAL v1.1)
- 기존 대안: 동네 범용 모임(당근 등)은 가입형이고 난이도·코스·종료가 가봐야 알 수 있다. 러닝 앱(NRC·러너온·크루업 등)은 기록·경쟁·인증 중심이다. (BRAND 차별점)
- 지금: 브랜드·랜딩·카피가 확정됐고 대기자 페이지가 배포 트랙에 있다. 앱의 플로우와 핵심 화면이 아직 없다.

## 2. 목적·목표 (측정 가능한 문장)

서비스 목적: 운동이 막막한 사람도 퇴근 후 동네에서 다 같이 걷고 달리고 자전거 타는 모임에 한 번씩 가볍게 참여하게 한다. (핵심 메시지)

이 라운드 목표 (MANUAL §2)
- G-01 리서치: research/01~05 전부, 페르소나 2 · 시나리오 3, 인터뷰 3~5명 완료, 페르소나·시나리오 문장마다 출처
- G-02 유저 플로우: 동행자 플로우 1(찾기 → 신청 → 체크인 → 해산 → 지도) + 길잡이 플로우 1(개설 → 모집 → 진행 → 종료) + 화면 목록·IA 1
- G-03 앱 화면 4장이 390 기준 impeccable BLOCKER 0 · MAJOR ≤2, DESIGN.md 완성 점검 통과

## 4. 타깃 사용자 (누가·어디서·얼마나 자주)

- 20대 초반~30대 후반 직장인, 혼자 사는 사람 위주, 남녀 모두. 운동이 막막하거나 동호회가 부담스러운 사람. 서울 우선. (헤드)
- 시간대: 퇴근 후 평일 저녁(산책·조깅·라이트 바이크), 주말 반나절(하이킹). 빈도는 정해지지 않음 — 가고 싶은 날만 한 번씩. (헤드, 일회성 구조)
- 역할 2: 모임을 여는 **길잡이**(본인인증 필수, 누구든 열면 그 회차의 길잡이) / 따라가는 **동행자**. (헤드, MANUAL §4 용어)
- 헤드가 정한 세그먼트 2 (MANUAL §4):
  - S1 20대 후반 남성, 서울·수도권 자취 직장인, 러닝·헬스 정기, 스포츠 경험 어느 정도 → 길잡이 후보 세그먼트 [가설 H-06]
  - S2 20대 중반 여성, 직장인, 운동 관심은 있으나 귀찮아서 자주 안 함, 가벼운 산책·자전거에 흥미 → 주 동행자 세그먼트 (브랜드 타깃과 일치)

## 5. 요구사항

기능 (MANUAL §5 그대로)
- F-01 동네·시간대·활동(산책·조깅·하이킹·라이트 바이크)으로 회차를 찾는다
- F-02 회차 상세에 코스·거리·난이도·출발·해산 시간·정원·길잡이 인증 여부(라이트 바이크면 따릉이 예상 요금)가 신청 전에 보인다
- F-03 회차 단위로 신청한다 — 가입도 참가비도 없다. 악천후 취소 시 "취소됨" 상태와 알림이 있다
- F-04 당일 체크인으로 모임이 시작되고 해산 시간에 종료된다
- F-05 이동 기록은 체크인~해산 사이에만 켜지고, 기본 공개 범위는 나만 보기, 공유는 본인 선택
- F-06 완주한 코스가 내 동네 지도에 채워진다(수집형). 순위·비교·스트릭 없음. 방금 완주 코스 1개만 Accent
- F-07 본인인증한 사람만 회차를 열 수 있고, 여는 순간 그 회차의 길잡이가 된다. 개설 시 코스·거리·해산 시간·정원 필수
- F-08 모든 모임 화면에서 신고에 2탭 안에 닿는다. 동행자 간 연락처·DM 없음
- F-09 라이트 바이크 회차는 따릉이 예상 요금(이용권 종류·코스 시간 기준)을 회차 상세에 표시하고 "따릉이로 이동"으로 따릉이 앱을 연다. 대여·결제·인증은 따릉이에서. 기존 이용권 보유자는 요금 0

비기능
- N-01 WCAG 2.1 AA — DESIGN.md 검증 조합만, 터치 44, 색만으로 상태 구분 금지
- N-02 위치 데이터 최소 수집 — 모임 시간 밖 기록 없음, 집 근처 출발·도착 노출 없음
- N-03 금지어(외로움·만남·인연·설렘) 0, 기록·순위·출석 압박 언어 0, 가짜 수치·후기 0
- N-04 색·글자·간격은 DESIGN.md 토큰 밖 값 금지, Accent는 화면당 1곳

## 6. 제약

- 기술: 앱 화면은 순수 HTML/CSS/JS 프로토타입(화면당 1파일), DESIGN.md 토큰을 `:root` CSS 변수로. 백엔드 없음. 렌더 검수는 Playwright(Claude Code) 또는 agent-browser(Cowork). (MANUAL §9)
- 일정: 목표일 없음, 순서가 게이트(M1 → M2(완료) → M3 → M4). 인터뷰 3~5명은 헤드가 직접. (MANUAL §7)
- 예산: 유료 도구·호출 없음 — 무료 범위(Figma, Google Fonts, Apps Script, Vercel 무료, 21st review 로컬)로만. 유료 호출은 위임 표 ASK. (헤드 확정)
- 브랜드: Primary #1E3A4C · Accent #FFB547(화면당 1곳) · Noto Sans KR + Archivo · 로고 루트 라인 모티프. 보이스: "또 와요" O / "꼭 와야 해요" X. (BRAND.md)
- 규정: 이동 기록 = 개인위치정보 → 앱 출시 전 위치정보법(사업 신고·별도 동의·보유·파기) 확인 필수. 대기자 페이지의 이메일·동네는 개인정보처리방침 필요. (MANUAL R-02, LAUNCH-CHECK)
- 안전: 초면·혼성·야외 모임. 규칙 5(참가비 없음·악천후 취소 알림 / 코스·해산 사전 공개 / 본인인증 길잡이 / 개인 연락 강요 금지·신고 / 이동 기록 모임 시간만·기본 비공개)를 화면 단계에 매핑해야 한다. (COPY 규칙 01~05)
