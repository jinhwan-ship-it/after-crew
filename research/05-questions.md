## 시나리오 피드백 (5)

1. **빈 데이터 상태가 없다.** → 헤드 결정 D-M3-01(flows/00-m3-inputs.md): 없음을 표시 + 새로고침 + 근처 동네 추천. SC-1 #1은 동네에 회차가 있다고 가정한다. 첫 오픈 동네 밖이거나 회차가 0개인 날, A 화면이 뭘 보여주는지가 없다 → M3에서 A의 빈 상태(대기·다른 동네 보기·알림 신청)를 정의해야 한다.
2. **길잡이 쪽 취소·노쇼가 없다.** SC-3은 동행자 노쇼만 다룬다. 길잡이가 못 오면 회차 전체 취소(F-03)와 연결되는데, 누가·언제까지 취소할 수 있는지 규칙이 없다 → H-20·H-21 질문에 길잡이 입장도 넣었다.
3. **기록 중 신호 끊김.** → 헤드 결정 D-M3-02: 완주 = 체크인·해산, 기록은 부가. SC-1 #7~9의 이동 기록(F-05)이 GPS·네트워크가 끊길 때 어떤 상태인지 없다. 완주 판정이 기록에 의존하면 끊김이 곧 "미완주"가 된다 → M3에서 "체크인·해산 = 완주, 기록은 부가"로 둘지 결정.
4. **코스 → 회차 역탐색은 매뉴얼 미규정.** → 헤드 결정 D-M3-03: 코스는 길잡이가 설정, 기존 코스 추천, D에서 코스 → 회차 연결 유지. SC-2 #1(지도의 빈 코스를 눌러 회차 목록으로)은 F-01·F-06 어디에도 없는 결합 기능이다. 좋은 진입점이지만 M3 IA에서 넣을지 결정하고, 넣으면 STATUS 잠금 후 결정에 기록.
5. **E-03(결정 추적)은 시나리오로 못 잡는다.** 정상 — 인터뷰가 아니라 §11·변경 이력이 답한다. 질문 배분에서 뺐다.
